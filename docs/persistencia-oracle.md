# Persistência Oracle do EasifyAI
 
Fonte do modelo: `easifybddoc.pdf`, lido integralmente (cinco páginas), especialmente
as descrições das páginas 3-4 e o diagrama da página 5. O PDF não contém os scripts
DDL/DML mencionados no texto. O SQL deste projeto é uma implementação do diagrama,
não uma cópia de um script oficial que não foi fornecido.
 
## Comparação da implementação
 
| Antes | PDF / implementação nova |
|---|---|
| H2 em arquivo, dependência runtime | Oracle JDBC `ojdbc11`, versão gerenciada pelo Spring Boot. H2 apenas em testes. |
| Três tabelas | Cinco tabelas: ANALISE, ANALISE_DOR, ANALISE_CONCORRENTE, TRANSCRICAO, STATUS_ACOMPANHAMENTO. |
| ANALISE.ID VARCHAR(36), PK UUID | ID NUMBER automático, PK interna. UUID_ANALISE VARCHAR2(36 BYTE), obrigatório e único. |
| FK das coleções por UUID | FK NUMBER apontando para ANALISE.ID. |
| VARCHAR e INTEGER H2 | VARCHAR2 com semântica BYTE e NUMBER conforme o diagrama. |
| Sem datas | DATA_CRIACAO, DATA_REGISTRO, DATA_MUDANCA, todos TIMESTAMP obrigatórios. |
| Transcrição descartada depois da análise | Texto integral persistido em TRANSCRICAO, em transação com a análise e suas coleções. |
| Sem acompanhamento | Histórico de eventos, com status, observação opcional e data. |
| Credenciais fixas e DDL ao iniciar | Credenciais externas e provisionamento SQL separado. |
 
A restrição antiga `POSICAO >= 0` não é recriada no SQL: o documento não a especifica.
O Java continua numerando coleções a partir de zero, preservando ordem e repetições.
Não foram criadas tabelas de pessoa, cliente ou vendedor: o PDF mantém esses dados
como colunas de ANALISE. Não há JPA/Hibernate neste projeto e não foi introduzido ORM.
 
## Dicionário extraído do diagrama
 
Todos os campos abaixo são NOT NULL, exceto STATUS_ACOMPANHAMENTO.OBSERVACAO.
 
| Tabela | Colunas e tipos |
|---|---|
| ANALISE | ID NUMBER (PK); UUID_ANALISE VARCHAR2(36 BYTE) (UNIQUE); CLIENTE_NOME, CLIENTE_EMPRESA, VENDEDOR_NOME VARCHAR2(500 BYTE); PRODUTO_RECOMENDADO CLOB; NIVEL_INTERESSE, RISCO_CHURN VARCHAR2(20 BYTE); PROXIMA_ACAO, RESUMO CLOB; DATA_CRIACAO TIMESTAMP. |
| ANALISE_DOR | ANALISE_ID NUMBER (FK), POSICAO NUMBER; PK composta (ANALISE_ID, POSICAO); DESCRICAO CLOB. |
| ANALISE_CONCORRENTE | ANALISE_ID NUMBER (FK), POSICAO NUMBER; PK composta (ANALISE_ID, POSICAO); DESCRICAO CLOB. |
| TRANSCRICAO | ID NUMBER (PK); ANALISE_ID NUMBER (FK, UNIQUE); TEXTO_ORIGINAL CLOB; DATA_REGISTRO TIMESTAMP. |
| STATUS_ACOMPANHAMENTO | ID NUMBER (PK); ANALISE_ID NUMBER (FK); STATUS VARCHAR2(20 BYTE); OBSERVACAO VARCHAR2(1000 BYTE), opcional; DATA_MUDANCA TIMESTAMP. |
 
Todas as FKs apontam para ANALISE.ID e têm ON DELETE CASCADE. As coleções e o
histórico são 1:N. O UNIQUE em TRANSCRICAO.ANALISE_ID permite no máximo uma
transcrição por análise; o caso de uso garante sua criação junto à análise.
Interesse e risco aceitam BAIXO, MEDIO, ALTO ou NAO_IDENTIFICADO.
 
Decisões necessárias porque o PDF não fornece o DDL:
 
- IDs numéricos das três tabelas com ID próprio usam `GENERATED BY DEFAULT ON NULL
  AS IDENTITY` (Oracle 12c+). Nenhuma sequence nomeada foi inventada. O DAO solicita
  a coluna ID em `getGeneratedKeys`, mantendo o UUID exclusivamente na coluna própria.
- Os estados descritos em português foram representados pelos literais PENDENTE,
  EM_ANDAMENTO, CONCLUIDO e DESCARTADO. Não se presume uma regra de transição nem
  se cria um status automaticamente a partir do resultado da Gemini.
- Datas usam CURRENT_TIMESTAMP; o DAO informa essas datas explicitamente. O DDL
  também fornece defaults para facilitar inserts manuais. TIMESTAMP não armazena fuso.
- Os nomes de PK/FK/UNIQUE seguem o diagrama. Os nomes dos CHECKs foram definidos
  neste script porque não aparecem no PDF.
 
## Arquitetura e comportamento
 
`POST /analisar` mantém o JSON e o UUID de resposta existentes. Controller delega a
`AnalisarTranscricaoUseCase`, que valida o texto, chama `Analisador` e persiste via
`AnaliseRepository`. O texto enviado para análise continua aparado; o texto salvo é
exatamente o original, inclusive espaços e quebras de linha.
 
`AnaliseDAO` traduz UUID para ID numérico dentro da infraestrutura. A transação grava
ANALISE, dores, concorrentes e TRANSCRICAO, com rollback em caso de falha. Atualizar
uma análise preserva ID, UUID, data de criação, transcrição e histórico. Excluir a
análise remove os dependentes por cascade. Consultas compostas continuam usando
isolamento SERIALIZABLE, como na implementação anterior.
 
O repositório oferece `buscarTranscricao`, `registrarStatus` e `listarHistorico`.
O registro de status acrescenta um evento; não sobrescreve registros anteriores.
Retorna false para uma análise inexistente. Não foram acrescentados endpoints de
gestão de status, pois a API existente só oferece a análise de transcrições.
`RegistroAcompanhamento` e `StatusAcompanhamento` representam esses dados sem JDBC.
 
Cliente e Vendedor continuam especializando Pessoa; as regras comerciais de
AnaliseTranscricao e seu polimorfismo não mudaram. Os IDs físicos não vazam para a API.
CLOBs são escritos por JDBC com Reader, inclusive quando vazios, sem truncamento ou
conversão para VARCHAR2. Os limites em bytes são aplicados pelo Oracle, sem truncar
silenciosamente conteúdo. H2 não reproduz integralmente a semântica BYTE do Oracle.
 
## Configuração local
 
Configure no ambiente do processo (terminal ou configuração de execução da IDE):
 
| Variável | Uso / valor padrão |
|---|---|
| DB_USERNAME | Obrigatória. Usuário do schema; na conexão local informada, RM566379. |
| DB_PASSWORD | Obrigatória. Senha configurada localmente, fora dos arquivos. |
| GEMINI_API_KEY | Obrigatória para a integração real, por configuração externa. |
| DB_HOST | Opcional: oracle.fiap.com.br. |
| DB_PORT | Opcional: 1521. |
| DB_SID | Opcional: ORCL. |
| DB_URL | Opcional: substitui a URL completa. Padrão usa jdbc:oracle:thin:@host:porta:SID. |
| GEMINI_MODEL | Opcional: gemini-2.5-flash. |
 
FIAP é o nome da conexão no SQL Developer; não é o nome de um serviço JDBC.
As propriedades `spring.datasource.*` são consumidas pela fábrica JDBC existente,
sem depender de autoconfiguração JPA. Um arquivo `.env` não é carregado automaticamente.
Não coloque usuário/senha dentro de DB_URL.
 
Depois de configurar as variáveis e preparar o schema, execute:
 
```powershell
.\mvnw.cmd spring-boot:run
```
 
A conexão é aberta no momento da operação; subir o contexto sozinho não confirma
conectividade com Oracle. A aplicação não cria, altera ou apaga tabelas no startup.
 
## Scripts e banco existente
 
- `src/main/resources/db/schema.sql`: criação das cinco tabelas, identity e constraints.
  Executar uma vez no schema destino, usando SQL Developer. Não usa schema pessoal
  hardcoded, DROP, IF NOT EXISTS ou atualização automática de estruturas.
- `src/main/resources/db/verificar-schema.sql`: consultas de metadados somente de leitura
  para comparar um schema já existente, inclusive defaults e geração de IDs.
- `src/main/resources/db/dados-desenvolvimento.sql`: exemplo fictício para as cinco
  tabelas, com rollback ao savepoint ao final. Rodar como script (F5). Não contém
  dados institucionais nem credenciais.
 
Se o banco FIAP já possui o modelo do PDF, não execute CREATE TABLE novamente:
compare os metadados com o script de verificação. Os dados antigos em `data/` não
são mais usados pela aplicação e não foram apagados. Não há conversão automática
dos dados H2: o modelo antigo não guardava a transcrição original, que não pode ser
reconstruída com fidelidade a partir dos resultados de análise.
 
## Segurança e validação
 
Foram removidas a chave Gemini literal de `application.properties` e as credenciais
demonstrativas de `ConexaoBanco`. A chave Gemini exposta precisa ser revogada pelo
responsável. Não há senha de banco ou chave API nova nos arquivos. `.gitignore`
passou a excluir configurações locais sensíveis.
 
Os testes de persistência executam o mesmo schema com H2 em modo Oracle, adaptando
apenas a declaração identity ao H2. Cobrem CRUD, UUID único, transcrição única,
histórico, cascatas, FKs, status inválido, rollback e preservação das regras comerciais.
Os testes HTTP verificam o UUID e a transcrição efetivamente persistidos. A integração
Gemini continua isolada nos testes. Execute `./mvnw.cmd -B -ntp verify`.
 
Validação realizada em 11/09/2026: `mvnw.cmd -B -ntp verify` terminou com
BUILD SUCCESS e 56 testes, sem falhas, erros ou testes ignorados. O contexto Spring
Boot iniciou no teste, com configurações locais de teste. O JAR inclui ojdbc11
23.9.0.25.07 e não inclui H2. Houve avisos do Mockito/Byte Buddy sobre carregamento
dinâmico de agente no Java 21, sem falha de compilação ou teste.
 
A conexão real depende das variáveis locais e não foi validada nesta execução.
H2 não substitui a validação do driver, dos CLOBs e dos limites em bytes no Oracle.
O diretório disponibilizado não contém `.git`, portanto não foi possível inspecionar
histórico, índice ou diff Git. A revisão de credenciais é sobre os arquivos locais.
